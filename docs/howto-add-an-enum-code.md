# How to add a country, language or currency code

This guide shows how to add a code to `country.Code`, `language.Code` or
`money.Currency`, regenerate the enum methods, and pass the checks that CI
runs. The three types are string enums marked `//#enum`; their `Enums()` and
`EnumStrings()` methods are generated by go-enum from the constants.

## Prerequisites

- A clone of the repository, with your working directory at its root.
- Go 1.26 or later. go-enum v1.1.0 is pinned as a tool in `tools/go.mod`, a
  separate module, so `go tool` downloads it on the first run. That run needs
  network access or a module cache that already has it.
- `bash`, to run `./run-go-enum.sh`.

The examples use the placeholder codes `QZ`, `qz` and `QZD`. Replace them
with the real code and name.

## Steps

### 1. Add the constant to the file that declares the type

go-enum collects the enum values of a type only from the file that declares
it, so the constant must go into that file's constant block:

| Type             | File                | Add to the `const` block after the type       |
|------------------|---------------------|-----------------------------------------------|
| `country.Code`   | `country/code.go`   | `QZ Code = "QZ" // Example Land`              |
| `language.Code`  | `language/code.go`  | `QZ Code = "qz" // Examplish`                 |
| `money.Currency` | `money/currency.go` | `QZD Currency = "QZD" // Example Land Dollar` |

Write the constant with an explicit type, as in the table. The position in the
block is the position in `Enums()`: the generated list follows declaration
order, which is why `XK` comes last in `country.Code("").Enums()`.

Language codes are lower case, country and currency codes upper case.

### 2. Add the code to the lookup tables

`Valid`, `Validate` and `Normalized` don't look at the constants; they look up
hand-written tables. Add the code there too:

**Country:**

- `countryMap` in `country/data.go`, required: `QZ: "Example Land",`. This is
  the English name returned by `EnglishName` and matched by `ParseCode`. Use a
  name no other code has: `ParseCode` builds a reverse index from the names,
  and with two codes sharing a name the result would depend on map iteration
  order.
- `euCountries` in `country/data.go`, if the country is an EU member:
  `QZ: {},`.
- `AltCodes` in `country/data.go`, for other spellings that `Normalized`
  accepts: `"EXAMPLELAND": QZ,`. Write the key in upper case without
  surrounding whitespace, because `Normalized` upper-cases and trims the input
  before the lookup.
- `idRegex` in `vat/formats.go`, if `vat.ID` should accept VAT IDs of the
  country: `` "QZ": regexp.MustCompile(`^QZ\d{9}$`), ``. Without an entry,
  `vat.ID` rejects them as an unsupported country code.
- `checkSumFuncs` in `vat/formats.go`, if the VAT ID has a checksum:
  `"QZ": checkSumQZ,` with a `func checkSumQZ(raw, normalized ID) bool`. A
  country without an entry is checked by format only.

**Language:**

- `codeNames` in `language/constants.go`, required: `"qz": "Examplish",`.
  Separate synonyms with `; `, like `"ca": "Catalan; Valencian"`;
  `ParseCode` matches each synonym on its own.
- `iso6393To1` in `language/iso6393.go`: an entry for the three-letter
  ISO 639-3 code, `"qzx": QZ,`, plus one for the ISO 639-2/B code where it
  differs, the way German has `"deu": DE, "ger": DE,`. `Normalized` resolves
  three-letter input through this table.

`iso6393names.go` and `iso6393macro.go` hold ISO 639-3 data generated from
the SIL tables. A new ISO 639-1 code doesn't require them to change;
`go generate ./language/...` refreshes them and needs network access.

**Currency:**

- `currencyCodeToName` in `money/constants.go`, required:
  `QZD: "Example Land Dollar",`. Every English name must be unique and must
  normalize back to its own code; a test checks this.
- `currencyCodeToISOName` in `money/constants.go`, if the official ISO 4217
  name has two or more words and differs from the English name.
- `currencySymbolToCode` and `currencyCodeToSymbol` in `money/constants.go`,
  if the currency has a symbol that should normalize to it or be returned by
  `Symbol()`.

### 3. Regenerate the enum methods

```sh
./run-go-enum.sh
```

The script runs `go tool -modfile=tools/go.mod go-enum ./...` from the
repository root. It rewrites `Enums()` and `EnumStrings()` of the changed type
in the same file. `Valid`, `Validate` and `String` carry a `// #custom` line
in their doc comment, so go-enum keeps the hand-written versions, which accept
non-normalized input.

### 4. Run the tests

```sh
go test ./...
```

These tests tie the constants to the tables:

| Test                                               | Checks                                             |
|----------------------------------------------------|----------------------------------------------------|
| `TestCode_EnumsMatchCountryMap` (country)          | `Enums()` equals the keys of `countryMap`          |
| `TestCode_EnglishName` (country)                   | every enum value has an English name               |
| `TestCode_EnumsMatchCodeNames` (language)          | `Enums()` equals the keys of `codeNames`           |
| `TestCurrency_EnumsMatchCurrencyCodeToName` (money) | `Enums()` equals the keys of `currencyCodeToName`  |
| `TestCurrency_NamesResolveToTheirCurrency` (money) | every English and ISO name normalizes to its own code |
| `TestCurrency_SymbolTableAndEnumStrings` (money)   | every symbol maps to an enum value                 |

### 5. Run what CI runs

The workflow `.github/workflows/go.yml` runs on every push and pull request
to `master`, with Go 1.26. Run its steps locally before you push:

```sh
go build -v ./...
go vet ./...
./run-go-enum.sh -validate
go test -count=1 -v ./...
```

The CI step "Validate go-enum methods" runs
`go tool -modfile=tools/go.mod go-enum -validate ./...`, which is what
`./run-go-enum.sh -validate` does. It changes no file and fails if a
generated method is missing or stale.

## Verification

Run this program from a directory inside the repository, with the three
constants replaced by the ones you added. Each line should print `true true`
and the name, and parsing the name should give the code back. For a language
name with synonyms, parse one synonym instead of the whole name:

```go
package main

import (
	"fmt"
	"slices"

	"github.com/domonda/go-types/country"
	"github.com/domonda/go-types/language"
	"github.com/domonda/go-types/money"
)

func main() {
	// Replace the three constants with the ones you added.
	c := country.XK
	l := language.ZU
	m := money.ZWG

	fmt.Println(c.ValidAndNormalized(), slices.Contains(c.Enums(), c), c.EnglishName())
	fmt.Println(country.ParseCode(c.EnglishName()))

	fmt.Println(l.ValidAndNormalized(), slices.Contains(l.Enums(), l), l.LanguageName())
	fmt.Println(language.ParseCode(l.LanguageName()))
	fmt.Println(language.Code("zul").Normalized()) // the ISO 639-3 code

	fmt.Println(m.ValidAndNormalized(), slices.Contains(m.Enums(), m), m.EnglishName())
	fmt.Println(money.Currency(m.EnglishName()).Normalized())

	// Output:
	// true true Republic of Kosovo
	// XK <nil>
	// true true Zulu
	// zu <nil>
	// zu <nil>
	// true true Zimbabwe Gold
	// ZWG <nil>
}
```

Then check that `git diff` shows changes only in the files you edited and in
the `Enums()` and `EnumStrings()` methods of the changed type.

## Troubleshooting

**CI or `./run-go-enum.sh -validate` fails with
`go-enum error: found 2 missing or outdated enum method(s)`,** preceded by
one line per stale method, like
`/path/to/go-types/country/code.go:527:1: missing or outdated Replacement for Code`.
The generated `Enums()` and `EnumStrings()` don't list the new constant yet.
Run `./run-go-enum.sh` and commit the regenerated file.

**The new code is missing from `Enums()`, although `./run-go-enum.sh` ran and
`-validate` passes.**
The constant is declared in another file than the type, for example in
`country/data.go`. go-enum doesn't see it, so it neither adds it nor reports
it. The tests catch it: `TestCode_EnumsMatchCountryMap` fails with
`Enums() = [...] want the countryMap keys [...]`. Move the constant into the
`const` block of `code.go` or `currency.go` and run `./run-go-enum.sh` again.

**An empty sentinel shows up in `Enums()`.**
A constant like `Invalid Code = ""` is a typed enum constant, so go-enum lists
it. Declare sentinels as conversions, the way the packages do:
`const Invalid = Code("")` in `country`, `const Null = Code("")` in
`language`. `money.CurrencyNull` is an untyped constant in
`money/constants.go`; keep it there.

**After regeneration `Code("de").Valid()` is false, or `String()` stops
normalizing.**
The `// #custom` line was removed from the doc comment of `Valid`, `Validate`
or `String`, and go-enum replaced the method with its generated exact-match
version. Restore the hand-written method with its `// #custom` line;
`git diff` shows the replaced body. `TestCode_CustomMethodsAndInvalidSentinel`,
`TestCode_ValidateStringAndNullSentinel` and
`TestCurrency_CustomMethodsAcceptNonNormalizedInput` fail until then.

**`TestCode_EnglishName` fails with `enum value "QZ" has no English name`.**
The `countryMap` entry is missing.

**`TestCurrency_NamesResolveToTheirCurrency` fails for the new currency.**
Its English name is not unique, so the name index maps it to another code.
Choose a distinct name, for example with "New" for a redenominated currency,
like the existing `AZN` ("Azerbaijan New Manat").

**`vat.ID` rejects IDs of the new country with `has an unsupported country
code: "QZ"`.**
`vat/formats.go` has no `idRegex` entry for the country.

**An `AltCodes` spelling doesn't normalize.**
The key is not upper case or has surrounding whitespace. `Normalized` looks
up the trimmed, upper-cased input.
