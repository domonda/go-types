# language

ISO 639-1 two-letter language codes. `Code` normalizes the language identifiers found in HTTP headers, locales and other standards (`"EN"`, `"deu"`, `"ger"`, `"en-US"`, `"zh_Hant"`) to the canonical lower-case ISO 639-1 code, returns English language names, and reads and writes SQL. Two lookup functions cover the full ISO 639-3 tables. The `date` package uses `Code` as a parsing hint.

    import "github.com/domonda/go-types/language"

## Code

```go
type Code string //#enum

const Null = Code("")
```

`Value` writes `Null` as SQL NULL and `Scan` reads SQL NULL as `Null`. The constant is declared as a conversion so that go-enum leaves it out of `Enums()`. `Null` is not a valid code: `Null.Valid()` is false and `Null.Validate()` returns an error. There is no nullable code type in this package.

### Constants

The package declares 184 `Code` constants, one per ISO 639-1 code, named after the upper-case code with a lower-case value: `EN Code = "en"`, `DE Code = "de"`, `ZH Code = "zh"`, ... Note that `language.EL` is Greek, unrelated to `country.EL`.

List them with the go-enum generated methods. Both return the codes in declaration order, which is close to alphabetical by English name:

```go
codes := language.Code("").Enums()       // []language.Code{language.AA, language.AB, language.AF, ...}
names := language.Code("").EnumStrings() // []string{"aa", "ab", "af", ...}
```

### Functions and methods

| Identifier                   | Description                                        |
|------------------------------|----------------------------------------------------|
| `ParseCode(str)`             | Canonical code from a code, tag or English language name, see below. |
| `Normalized()`               | The canonical ISO 639-1 code for the input shapes listed below. On failure returns the input unchanged and an error that quotes it. |
| `Valid()`                    | Strict: true only for a canonical lower-case ISO 639-1 code. `Code("EN").Valid()` is false. |
| `Validate()`                 | Lenient: the error of `Normalized()`, or nil. `Code("EN").Validate()` is nil. |
| `ValidAndNormalized()`       | True only for a canonical code; same result as `Valid()`. |
| `LanguageName()`             | English name from the ISO 639-1 table. Normalizes first; `""` if invalid. |
| `String()`                   | Normalized code, or the raw string if invalid.     |
| `Enums()`, `EnumStrings()`   | All 184 codes, generated by go-enum.               |
| `ISO6393Name(code)`          | English reference name of an ISO 639-3 code (`"deu"` gives `"German"`), `""` if unknown. |
| `ISO6393Macrolanguage(code)` | ISO 639-3 macrolanguage of an individual language (`"twi"` gives `"aka"`), `""` if none. |

Implements: `fmt.Stringer`, `database/sql.Scanner`, `database/sql/driver.Valuer`, `types.NormalizableValidator[Code]` and `JSONSchema()` (`{"type":"string","pattern":"^[a-z]{2}$"}`). `Code` has no JSON methods and no `ScanString` method, so it is not a `strfmt.Scannable`.

`Valid`, `Validate` and `String` are hand-written and carry a `// #custom` marker, so go-enum keeps them. `Valid` is strict on purpose; `Validate` normalizes first like `country.Code` and `money.Currency`.

### Normalized input shapes

`Normalized()`, and so `Validate()`, `LanguageName()` and `String()`, accept:

- ISO 639-1 codes in any case with surrounding whitespace: `"en"`, `"EN"`, `" en "`.
- ISO 639-2/T and ISO 639-3 codes that have an ISO 639-1 equivalent: `"eng"`, `"deu"`, `"fra"`.
- ISO 639-2/B bibliographic codes: `"ger"` gives `"de"`, `"fre"` gives `"fr"`, `"chi"` gives `"zh"`.
- BCP-47 tags and POSIX locales, using only the primary subtag: `"en-US"`, `"zh-Hant-CN"`, `"sr-Latn"`, `"en_US"`.

ISO 639-3 codes without an ISO 639-1 equivalent (most of the roughly 7900 codes, like `"abq"`) are rejected.

### ParseCode

`ParseCode(str)` tries the cheapest interpretation first:

1. A canonical code (`"en"`) is returned as is.
2. Anything `Normalized` accepts.
3. An English language name, matched case-insensitively: `"German"`, `"english"`, `"Valencian"`. Names come from the ISO 639-1 table, including each synonym of entries like `"Catalan; Valencian"`, and from the ISO 639-3 names of languages that have an ISO 639-1 code. The ISO 639-1 names win on conflicts.

On failure it returns the input unchanged and the error of `Normalized`.

### ISO 639-3 lookups

`ISO6393Name` and `ISO6393Macrolanguage` read tables generated from the SIL ISO 639-3 data. Both are case-sensitive and expect the canonical lower-case code: `ISO6393Name("DEU")` is `""`. A code with several names returns its primary name. A macrolanguage is not a member of itself (`ISO6393Macrolanguage("aka")` is `""`), and retired mappings are not returned.

## Serialization

| Value                  | SQL `Value()`           | JSON (`json.Marshal`) | `String()` |
|------------------------|-------------------------|-----------------------|------------|
| `Null`                 | `NULL`                  | `""`                  | `""`       |
| `Code("en")`           | `"en"`                  | `"en"`                | `"en"`     |
| `Code("EN")`           | `"EN"` (not normalized) | `"EN"`                | `"en"`     |
| `Code("xx")` (invalid) | `"xx"`, no error        | `"xx"`                | `"xx"`     |

| Input                          | Result                                  |
|--------------------------------|-----------------------------------------|
| `Scan(nil)`                    | `Null`                                  |
| `Scan(string)`, `Scan([]byte)` | stored as is, not normalized or checked |
| `Scan` of other types          | error                                   |
| JSON string                    | stored as is, not normalized or checked |
| JSON `null`                    | field left unchanged                    |

## Gotchas

- **`Valid` is strict, `Validate` is lenient.** `Code("EN").Valid()` is false while `Code("EN").Validate()` is nil. `types.Validate`, `types.DeepValidate` and `strfmt` scanning call `Validate`, so they accept `"EN"`, `"eng"` and `"en-US"` and store them unchanged. Call `Normalized` before storing, or check `Valid` to require the canonical form.
- **`Value` does not normalize.** `Code("EN")` is written to SQL as `"EN"`, unlike `country.Code`, which writes normalized codes.
- **Optional languages.** `Null` is SQL NULL but fails `Validate`, so an empty language field fails `types.DeepValidate`. Use a `*language.Code` for optional fields or check for `Null` before validating.
- **JSON is the plain string.** `Null` encodes as `""`, not `null`. The JSON schema pattern `^[a-z]{2}$` rejects `"EN"`, which `Validate` accepts.
- **English names must match a table entry.** `ParseCode("Greek")` fails, because the names are `"Greek, Modern (1453-)"` (ISO 639-1) and `"Modern Greek (1453-)"` (ISO 639-3).
- **Names may list synonyms.** `language.CA.LanguageName()` is `"Catalan; Valencian"`, `language.NL.LanguageName()` is `"Dutch; Flemish"`.
- **Tags lose detail.** `"zh-Hant"` and `"zh-Hans"` both normalize to `"zh"`.
- **Date parsing hints.** `date.Normalize` only distinguishes English from everything else, see the [`date`](../date/README.md) package.

## Examples

```go
package main

import (
	"fmt"

	"github.com/domonda/go-types/language"
)

func main() {
	for _, s := range []string{"en", "EN", "deu", "ger", "en-US", "zh_Hant", "German", "Klingon"} {
		c, err := language.ParseCode(s)
		fmt.Println(c, err)
	}

	c := language.Code("EN")
	fmt.Println(c.Valid(), c.Validate(), c.LanguageName())

	// Output:
	// en <nil>
	// en <nil>
	// de <nil>
	// de <nil>
	// en <nil>
	// zh <nil>
	// de <nil>
	// Klingon invalid language.Code: "Klingon"
	// false <nil> English
}
```

```go
package main

import (
	"fmt"

	"github.com/domonda/go-types/language"
)

func main() {
	// Value writes the raw string, normalize before storing
	v, _ := language.Code("EN").Value()
	fmt.Println(v)
	norm, _ := language.Code("EN").Normalized()
	v, _ = norm.Value()
	fmt.Println(v)

	fmt.Println(language.ISO6393Name("deu"), language.ISO6393Macrolanguage("twi"))
	fmt.Println(language.CA.LanguageName())
	fmt.Println(len(language.Code("").Enums()))

	// Output:
	// EN
	// en
	// German aka
	// Catalan; Valencian
	// 184
}
```

## Data files

| File              | Content                                            | Maintained by                               |
|-------------------|----------------------------------------------------|---------------------------------------------|
| `code.go`         | `Code`, its methods and the ISO 639-1 constants; `Enums()` and `EnumStrings()` at the end | hand; go-enum for `Enums` and `EnumStrings` |
| `constants.go`    | `codeNames`: ISO 639-1 code to English name        | hand                                        |
| `iso6393.go`      | `iso6393To1`: ISO 639-2/T, 639-2/B and 639-3 codes to ISO 639-1, and the two lookup functions | hand                                        |
| `iso6393names.go` | `iso6393Names`: ISO 639-3 code to English name     | `gen-lang-maps`                             |
| `iso6393macro.go` | `iso6393Macro`: individual language to macrolanguage | `gen-lang-maps`                             |

Refresh the two generated tables with `go generate ./language/...` (needs network access), see [`gen-lang-maps`](gen-lang-maps/README.md).

## Adding a language code

1. Add the constant to the `const` block in `language/code.go`: `XX Code = "xx" // Name`. It must live in the file that declares `type Code string //#enum`, because go-enum only reads that file.
2. Add `"xx": "Name"` to `codeNames` in `language/constants.go`. `TestCode_EnumsMatchCodeNames` fails if the two lists differ.
3. Add the ISO 639-2/T, 639-2/B and 639-3 codes of the language to `iso6393To1` in `language/iso6393.go`, so that `Normalized` maps them.
4. Run `./run-go-enum.sh` from the repository root to regenerate `Enums()` and `EnumStrings()`, then `go test ./...`.
5. CI runs `go-enum -validate` and fails if the generated methods are stale.

See [Add an enum code](../docs/howto-add-an-enum-code.md) for the full steps.
