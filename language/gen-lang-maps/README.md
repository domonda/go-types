# gen-lang-maps

Command `gen-lang-maps` regenerates the two ISO 639-3 tables of the [`language`](../README.md) package from the reference data that SIL International publishes as the ISO 639-3 registration authority. Run it when SIL releases new codes or names.

## Running

From the repository root:

```sh
go generate ./language/...
```

or directly:

```sh
go run ./language/gen-lang-maps
```

`go generate` finds the `//go:generate go run .` directive in `main.go`. The command needs network access to `iso639-3.sil.org`. It writes its output next to its own source file, found through `runtime.Caller`, so the working directory does not matter. Run it from source as shown; a binary built with `-trimpath` has no usable source path.

After a run, check the diff and run the tests:

```sh
go test ./language/...
```

`TestISO6393MapsPopulated` fails if a table came out nearly empty, and `TestISO6393MacroMembersHaveNames` fails if a macrolanguage mapping refers to a code without a name.

## What it does

1. Downloads two tab-separated files from the un-dated SIL URLs, which always serve the latest release:
   - `https://iso639-3.sil.org/sites/iso639-3/files/downloads/iso-639-3_Name_Index.tab`
   - `https://iso639-3.sil.org/sites/iso639-3/files/downloads/iso-639-3-macrolanguages.tab`

   It sends its own `User-Agent` header, because the SIL CDN answers Go's default one with 403. The date-stamped ZIP download used before is blocked by that CDN.
2. Sorts the rows by code and writes Go source:
   - **Names:** the first name of each code is the map entry; further names of the same code are kept as commented-out lines.
   - **Macrolanguages:** active mappings (status `A`) are map entries; retired mappings (status `R`) are kept as commented-out lines. Any other status stops the command.
3. Formats the source with `go/format` and overwrites the files, each marked `// Code generated by language/gen-lang-maps. DO NOT EDIT.`

Any download, parse or format error stops the command with a log message. The names file is written before the macrolanguages file is downloaded, so a failed second download leaves only the names file updated.

## Files

| File                       | Content                                            | Maintained by                                      |
|----------------------------|----------------------------------------------------|----------------------------------------------------|
| `language/iso6393names.go` | `iso6393Names`: ISO 639-3 code to English name     | this command                                       |
| `language/iso6393macro.go` | `iso6393Macro`: individual language code to macrolanguage code | this command                                       |
| `language/iso6393.go`      | `iso6393To1` (ISO 639-2/T, 639-2/B and 639-3 to ISO 639-1), `ISO6393Name`, `ISO6393Macrolanguage` | hand                                               |
| `language/constants.go`    | `codeNames`: ISO 639-1 code to English name        | hand                                               |
| `language/code.go`         | `Code` and the ISO 639-1 constants                 | hand, `Enums()` and `EnumStrings()` by `./run-go-enum.sh` |

The command does not touch the ISO 639-1 tables. A new ISO 639-1 code needs the manual steps in [Adding a language code](../README.md#adding-a-language-code).
